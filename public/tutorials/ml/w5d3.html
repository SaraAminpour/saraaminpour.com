Warm-up

Who gets the blame?

1 min

A network makes a wrong prediction. Which of its thousands of weights should change, and by how much? Since week 2 PyTorch has answered that for you with one line, loss.backward(). Today you open that line and see the idea inside: blame flows backward, step by step.

Big idea

Forward to compute, backward to blame

4 min

Write the network as a chain of small steps, a computational graph. For one hidden neuron:

x→  w1x+b1  z1→  tanh⁡  h→  w2h+b2  z2→  σ  p→  cross-entropy  Lx \xrightarrow{\;w_1x + b_1\;} z_1 \xrightarrow{\;\tanh\;} h \xrightarrow{\;w_2h + b_2\;} z_2 \xrightarrow{\;\sigma\;} p \xrightarrow{\;\text{cross-entropy}\;} Lxw1​x+b1​​z1​tanh​hw2​h+b2​​z2​σ​pcross-entropy​L

Forward pass: compute each value from the one before, and remember them all.

Backward pass: start from ∂L∂L=1\frac{\partial L}{\partial L} = 1∂L∂L​=1 and walk back. Each step multiplies the gradient arriving from the right by its own local slope. That's the chain rule:

∂L∂z2=p−y,∂L∂h=∂L∂z2 w2,∂L∂z1=∂L∂h (1−h2),∂L∂w1=∂L∂z1 x\frac{\partial L}{\partial z_2} = p - y, \qquad \frac{\partial L}{\partial h} = \frac{\partial L}{\partial z_2}\,w_2, \qquad \frac{\partial L}{\partial z_1} = \frac{\partial L}{\partial h}\,(1 - h^2), \qquad \frac{\partial L}{\partial w_1} = \frac{\partial L}{\partial z_1}\,x∂z2​∂L​=p−y,∂h∂L​=∂z2​∂L​w2​,∂z1​∂L​=∂h∂L​(1−h2),∂w1​∂L​=∂z1​∂L​x

The first one is a small gift: the loss's slope −1p-\frac{1}{p}−p1​ (for y=1y = 1y=1) times the sigmoid's slope p(1−p)p(1-p)p(1−p) simplifies to p−yp - yp−y, the same rule you met in week 3. Every weight's gradient appears along the way, for example ∂L∂w2=∂L∂z2 h\frac{\partial L}{\partial w_2} = \frac{\partial L}{\partial z_2}\,h∂w2​∂L​=∂z2​∂L​h. In a big network the same thing happens with matrices instead of single numbers.

One backward pass gives the gradient of every weight, for about the cost of one forward pass. That's what makes training networks with millions of weights possible.

The alternative, nudging each weight separately and re-running the network (finite differences), would cost one forward pass per weight. It's still useful, though, as a check that the gradients are right.

Backpropagation three ways

cell 1 · the forward pass
import math
import torch

torch.set_num_threads(1)
x, y = 1.0, 1.0                                   # one example
w1, b1, w2, b2 = 1.5, -0.5, -2.0, 0.5            # four knobs

z1 = w1 * x + b1
h = math.tanh(z1)
z2 = w2 * h + b2
p = 1 / (1 + math.exp(-z2))
L = -(y * math.log(p) + (1 - y) * math.log(1 - p))
print(f"forward:  z1 = {z1:.4f}, h = {h:.4f}, z2 = {z2:.4f}, p = {p:.4f}, loss = {L:.4f}")
What it printed in the notebook
forward:  z1 = 1.0000, h = 0.7616, z2 = -1.0232, p = 0.2644, loss = 1.3303
cell 2 · the backward pass, by hand
dz2 = p - y                       # sigmoid + cross-entropy: the famous p - y
dw2, db2 = dz2 * h, dz2           # z2 = w2*h + b2
dh = dz2 * w2
dz1 = dh * (1 - h ** 2)           # d tanh(z)/dz = 1 - tanh(z)^2
dw1, db1 = dz1 * x, dz1
print(f"by hand:  dL/dw1 = {dw1:.4f}, dL/db1 = {db1:.4f}, dL/dw2 = {dw2:.4f}, dL/db2 = {db2:.4f}")
What it printed in the notebook
by hand:  dL/dw1 = 0.6179, dL/db1 = 0.6179, dL/dw2 = -0.5602, dL/db2 = -0.7356
cell 3 · autograd agrees
W1, B1, W2, B2 = (torch.tensor(v, requires_grad=True) for v in (w1, b1, w2, b2))
P = torch.sigmoid(W2 * torch.tanh(W1 * x + B1) + B2)
loss = -(y * torch.log(P) + (1 - y) * torch.log(1 - P))
loss.backward()
print(f"autograd: dL/dw1 = {W1.grad:.4f}, dL/db1 = {B1.grad:.4f}, dL/dw2 = {W2.grad:.4f}, dL/db2 = {B2.grad:.4f}")
What it printed in the notebook
autograd: dL/dw1 = 0.6179, dL/db1 = 0.6179, dL/dw2 = -0.5602, dL/db2 = -0.7356
cell 4 · why backward wins
import time

net = torch.nn.Sequential(torch.nn.Linear(256, 256), torch.nn.Tanh(), torch.nn.Linear(256, 1))
n_params = sum(q.numel() for q in net.parameters())
xb = torch.randn(64, 256)
t0 = time.perf_counter()
out = net(xb).pow(2).mean()
t_forward = time.perf_counter() - t0
t0 = time.perf_counter()
out.backward()
t_backward = time.perf_counter() - t0
print(f"{n_params:,} parameters")
print(f"one forward pass:  {t_forward * 1000:.2f} ms")
print(f"one backward pass: {t_backward * 1000:.2f} ms  -> every gradient at once")
fd = n_params * t_forward
print(f"finite differences would need {n_params:,} forward passes: about {fd:.0f} seconds instead of {t_backward * 1000:.1f} ms")
print("and the gap grows with every parameter: for a network with a billion weights it's the difference between possible and not.")

one solution
def numeric_grad(params, i, eps=1e-6):
    up, down = list(params), list(params)
    up[i] += eps
    down[i] -= eps
    return (loss_of(*up) - loss_of(*down)) / (2 * eps)

for i, (name, exact) in enumerate(zip(["w1", "b1", "w2", "b2"], [dw1, db1, dw2, db2])):
    print(f"dL/d{name}: numeric {numeric_grad(params, i):.6f}   backprop {exact:.6f}")

Wrap-up

Today in one sentence

1 min
Backpropagation computes the network forward, then sends the gradient of the loss backward with the chain rule, so one backward pass yields the gradient of every weight; autograd does exactly this inside loss.backward().
Quantum link

Quantum hardware can't do this: looking at the intermediate amplitudes of a circuit would collapse them. So quantum circuits get their gradients with the parameter-shift rule (week 7 of Quantum Computing), which costs two extra circuit runs per parameter, much like finite differences. That cost is one of the big practical challenges of quantum machine learning.
