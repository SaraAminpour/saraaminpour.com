Warm-up

What the computer actually sees

1 min

Yesterday you met the iris flowers. You saw petals; the computer saw [5.1, 3.5, 1.4, 0.2]. Before any learning can happen, the world has to become numbers. Today: how that works, and where those numbers live in PyTorch.

  • A row is one example (one flower). Written as a vector, it's xi=(4.9, 3.0, 1.4, 0.2)x_i = (4.9,\ 3.0,\ 1.4,\ 0.2)xi​=(4.9, 3.0, 1.4, 0.2), the highlighted row.
  • A column is one feature: the same measurement for every example, like the petal length.
  • The label yiy_iyi​ is the answer column. Supervised learning has it; unsupervised learning doesn't.

All the features together form a matrix XXX with one row per example: nnn rows and ddd columns. For iris, n=150n = 150n=150 and d=4d = 4d=4, and in code that's simply X.shape == (150, 4).

Each example is a point in a ddd-dimensional feature space. Learning is finding patterns among those points.

Two practical details matter a lot:

Categories become one-hot vectors

A color red / green / blue is not a number. Writing 0, 1, 2 would claim that green sits "between" red and blue. Instead each category gets its own column: red =(1,0,0)= (1,0,0)=(1,0,0), green =(0,1,0)= (0,1,0)=(0,1,0), blue =(0,0,1)= (0,0,1)=(0,0,1).

Scales differ

A length in millimetres has numbers 10 times bigger than the same length in centimetres. Methods that measure distances get fooled, so we often standardize each feature: z=(x−μ)/σz = (x - \mu)/\sigmaz=(x−μ)/σ, giving mean 0 and spread 1.

A tensor is PyTorch's array: a grid of numbers with a shape and a type. A table of features is a 2D tensor.

cell 1 · the table as a tensor
import torch
from sklearn.datasets import load_iris

iris = load_iris()
X = torch.tensor(iris.data, dtype=torch.float32)   # features: one row per flower
y = torch.tensor(iris.target)                      # labels: 0, 1 or 2

print("X:", tuple(X.shape), X.dtype)
print("y:", tuple(y.shape), y.dtype)
print(X[:3])

Every column gets its own mean and spread. dim=0 means "go down the rows", giving one number per column:

cell 3 · summaries and standardizing
mean = X.mean(dim=0)         # dim=0: average down the rows, one number per column
std = X.std(dim=0)
Z = (X - mean) / std

print("means:          ", mean.round(decimals=2))
print("spreads (std):  ", std.round(decimals=2))
print("after: means    ", Z.mean(dim=0).round(decimals=2).abs())
print("after: spreads  ", Z.std(dim=0).round(decimals=2))

Your turn: the average flower

2 min

Compute the average flower of each species: the mean of each of the 4 features, over that species' rows only. Which feature differs the most between species?

exercise · in your notebook
for k, name in enumerate(iris.target_names):
    rows = X[y == k]
    average = None   # TODO: the mean of each column of `rows` (4 numbers)
    print(name, average)
Need a hint?

X[y == k] keeps the rows of species k. Then .mean(dim=0) averages down those rows.

Show a solution
one solution
for k, name in enumerate(iris.target_names):
    rows = X[y == k]
    average = rows.mean(dim=0)
    print(f"{name:>10}: sepal {average[0]:.2f} x {average[1]:.2f} cm, petal {average[2]:.2f} x {average[3]:.2f} cm")

print("\nPetal length changes the most (1.46 -> 4.26 -> 5.55 cm), which is why the petal plot separates the species so well.")

Wrap-up

Today in one sentence

1 min
A dataset is a table: rows are examples (points in feature space), columns are features, and the label is the answer column. PyTorch stores it as a tensor of shape (n, d).
Quantum link

A quantum model also needs its data as numbers, and then has to load them into qubits, for example by turning each feature into a rotation angle. With 4 qubits you could encode one iris flower, one feature per qubit. That loading step, data encoding, opens the Quantum ML tutorial.
