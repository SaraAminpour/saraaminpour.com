Warm-up

Two knobs by hand, a million by machine

1 min

Yesterday you wrote out the gradient of the pizza loss by hand: two formulas for two knobs. A neural network has millions of knobs. Nobody differentiates that by hand. PyTorch does it for you, and once you know its five-line loop you can train almost anything, including, in a few weeks, quantum circuits.

Big idea

Tensors, graphs and the loop

4 min

A tensor is PyTorch's version of a NumPy array. The magic flag is requires_grad=True: then every calculation that uses the tensor is recorded in a computational graph.

Calling loss.backward() walks that graph from the loss back to every knob, applying the chain rule at each step. This is backpropagation, and the result lands in each knob's .grad. For example, for L=(wx+b−y)2L = (wx + b - y)^2L=(wx+b−y)2 the chain rule gives

∂L∂w=2 (wx+b−y)⋅x∂L∂b=2 (wx+b−y)\frac{\partial L}{\partial w} = 2\,(wx + b - y)\cdot x \qquad \frac{\partial L}{\partial b} = 2\,(wx + b - y)∂w∂L​=2(wx+b−y)⋅x∂b∂L​=2(wx+b−y)

and autograd finds exactly these numbers without being told the formulas. Training is then always the same loop:

  1. optimizer.zero_grad(): clear old gradients (PyTorch adds to .grad, it never overwrites).
  2. prediction = model(X): the forward pass.
  3. loss = loss_fn(prediction, Y): one number saying how wrong we are.
  4. loss.backward(): the backward pass fills every .grad.
  5. optimizer.step(): move every knob a little downhill.

torch.nn.Linear(1, 1) is our line: it holds one weight www and one bias bbb. The optimizer decides how to step: SGD is plain gradient descent, while Adam keeps a running average of past gradients and adapts the step for each knob.

cell 3 · autograd agrees with the formulas
rng = np.random.default_rng(3)
x_cm = rng.uniform(20, 40, size=25)
price = 0.55 * x_cm - 2 + rng.normal(0, 1.4, size=25)
xs = (x_cm - x_cm.mean()) / x_cm.std()

X = torch.tensor(xs, dtype=torch.float32).reshape(-1, 1)      # 25 rows, 1 feature
Y = torch.tensor(price, dtype=torch.float32).reshape(-1, 1)

w = torch.tensor(0.0, requires_grad=True)
b = torch.tensor(0.0, requires_grad=True)
loss = ((w * X + b - Y) ** 2).mean()
loss.backward()
print("autograd:", round(w.grad.item(), 4), round(b.grad.item(), 4))
print("by hand :", round(2 * np.mean((0 - price) * xs), 4), round(2 * np.mean(0 - price), 4))
What it printed in the notebook

cell 4 · the training loop
torch.manual_seed(0)
model = torch.nn.Linear(1, 1)
optimizer = torch.optim.SGD(model.parameters(), lr=0.1)

losses = []
for step in range(100):
    optimizer.zero_grad()                              # 1. forget old gradients
    prediction = model(X)                              # 2. forward pass
    loss = torch.nn.functional.mse_loss(prediction, Y) # 3. how wrong are we?
    loss.backward()                                    # 4. backward pass: gradients
    optimizer.step()                                   # 5. nudge every knob downhill
    losses.append(loss.item())

print(f"w = {model.weight.item():.3f}, b = {model.bias.item():.3f}, final MSE = {losses[-1]:.3f}")
What it printed in the notebook
w = 2.800, b = 14.304, final MSE = 1.955

Same answer as Monday's formula and yesterday's hand-written loop.

Break it on purpose

In the notebook, delete optimizer.zero_grad() from the loop and run it again. PyTorch adds new gradients to the old ones, so the steps grow wrong. That's why line 1 exists.

Your turn: ten features at once

3 min

Real data has many features. The diabetes dataset describes 442 patients with 10 measurements each (age, body-mass index, blood pressure, six blood tests), and the target is a disease-progression score. The model is y^=w1x1+⋯+w10x10+b\hat y = w_1x_1 + \dots + w_{10}x_{10} + by^​=w1​x1​+⋯+w10​x10​+b, which in PyTorch is torch.nn.Linear(10, 1).

Write the training loop (500 steps) and compare your MSE with the exact least-squares answer. Then look at which weights are largest.

import numpy as np
from sklearn.datasets import load_diabetes
from sklearn.linear_model import LinearRegression

data = load_diabetes()
Xd = torch.tensor(data.data, dtype=torch.float32)
Xd = (Xd - Xd.mean(dim=0)) / Xd.std(dim=0)                        # standardize every column
Yd = torch.tensor(data.target, dtype=torch.float32).reshape(-1, 1)

torch.manual_seed(0)
model = torch.nn.Linear(10, 1)
optimizer = torch.optim.SGD(model.parameters(), lr=0.1)
# TODO: the five-line training loop, repeated 500 times

final = torch.nn.functional.mse_loss(model(Xd), Yd).item()
exact = LinearRegression().fit(Xd.numpy(), Yd.numpy())
best = np.mean((exact.predict(Xd.numpy()) - Yd.numpy()) ** 2)
print(f"PyTorch MSE: {final:.1f}   exact least squares: {best:.1f}")
Need a hint?

It's exactly the loop from cell 4, with Xd and Yd instead of X and Y. Because every feature is standardized, a bigger weight really does mean a more important feature.

one solution
torch.manual_seed(0)
model = torch.nn.Linear(10, 1)
optimizer = torch.optim.SGD(model.parameters(), lr=0.1)
for step in range(500):
    optimizer.zero_grad()
    loss = torch.nn.functional.mse_loss(model(Xd), Yd)
    loss.backward()
    optimizer.step()

final = torch.nn.functional.mse_loss(model(Xd), Yd).item()
print(f"PyTorch MSE: {final:.1f}   exact least squares: {best:.1f}")

# with standardized features, the weights can be compared: which measurements matter most?
weights = model.weight.detach().numpy().ravel()
order = np.argsort(-np.abs(weights))
print("largest weights:", ", ".join(f"{data.feature_names[i]} {weights[i]:+.1f}" for i in order[:4]))
print("bmi = body-mass index, bp = blood pressure, s1..s6 = blood measurements")

Wrap-up

Today in one sentence

1 min
PyTorch records how tensors are computed, so loss.backward() finds every gradient for you; training is always the same loop: zero the gradients, predict, compute the loss, backward, step.
