Warm-up

An exponential suitcase

1 min

Ten qubits have 1,024 amplitudes; fifty have more than a quadrillion. If each amplitude held one number of your data, a handful of qubits could hold an enormous dataset. That's amplitude encoding, and it's real. But a suitcase is only useful if packing and unpacking it don't take forever.

Big idea

Squeeze in, and the price

4 min

Amplitude encoding. Take a vector xxx with 2n2^n2n entries, normalize it, and use the entries as amplitudes:

∣x⟩=1∥x∥∑i=02n−1xi ∣i⟩|x\rangle = \frac{1}{\|x\|}\sum_{i=0}^{2^n - 1} x_i\,|i\rangle∣x⟩=∥x∥1​i=0∑2n−1​xi​∣i⟩

An 8 × 8 digit (64 pixels) becomes a state of just 6 qubits. Normalizing forgets the vector's length, so xxx and 2x2x2x become the same state; only the proportions survive.

The price of packing. A circuit must prepare that state from ∣00…0⟩|00\ldots0\rangle∣00…0⟩. For an arbitrary vector this takes on the order of 2n2^n2n CNOTs: 57 for our digit, about a million for 20 qubits. If loading the data costs as much as the computation could save, the advantage evaporates: the input problem. (A "quantum RAM" would help, but no large one exists.)

The price of unpacking. Measuring gives one basis state per shot, so estimating all 2n2^n2n amplitudes takes many shots, again growing with 2n2^n2n. Good quantum algorithms never read all the amplitudes; they only estimate a few expectation values.

Qubit budgets. Angle encoding: one qubit per feature, almost no gates. Amplitude encoding: log⁡2d\log_2 dlog2​d qubits, about ddd gates. Today's simulators manage about 30 qubits, and hardware is noisy, so the common recipe is: shrink the data with PCA (ML week 6), then angle-encode the few components left.

Amplitude encoding packs 2n2^n2n numbers into nnn qubits, but loading them costs about 2n2^n2n gates and reading them back about as many shots.

cell 1 · a digit as a 6-qubit state
import numpy as np
import matplotlib.pyplot as plt
from qiskit import QuantumCircuit, transpile
from qiskit.circuit.library import StatePreparation
from qiskit.quantum_info import Statevector
from sklearn.datasets import load_digits

digits = load_digits()
x = digits.data[0]                                  # a "0": 64 pixel values
amplitudes = x / np.linalg.norm(x)                  # a state must have length 1
state = Statevector(amplitudes)                     # 64 amplitudes = 6 qubits
print("qubits:", state.num_qubits)
print("probabilities = normalized pixels squared:", np.allclose(state.probabilities(), amplitudes ** 2))

cell 2 · the cost of preparing it
rng = np.random.default_rng(0)
ns, cnots = range(1, 9), []
for n in ns:
    v = rng.normal(size=2 ** n)
    qc = QuantumCircuit(n)
    qc.append(StatePreparation(v / np.linalg.norm(v)), range(n))
    cnots.append(transpile(qc, basis_gates=["cx", "u"], optimization_level=1).count_ops().get("cx", 0))
    print(f"{n} qubit{'s' if n > 1 else ' '} ({2 ** n:3d} numbers): {cnots[-1]:3d} CNOTs")

plt.semilogy(list(ns), np.maximum(cnots, 0.8), "o-", color="#ff7a59", label="CNOTs to prepare the state")
plt.semilogy(list(ns), 2.0 ** np.array(ns), "--", color="#8a85a3", label=r"$2^n$")
plt.xlabel("qubits n")
plt.legend()
plt.show()

cell 3 · reading it back
fig, axes = plt.subplots(1, 4, figsize=(8, 2.3), layout="constrained")
axes[0].imshow(x.reshape(8, 8), cmap="Purples")
axes[0].set_title("original")
for ax, shots in zip(axes[1:], [100, 1000, 100000]):
    counts = np.bincount(rng.choice(64, size=shots, p=amplitudes ** 2), minlength=64)
    estimate = np.sqrt(counts / shots)
    ax.imshow(estimate.reshape(8, 8), cmap="Purples")
    ax.set_title(f"{shots:,} shots, F = {np.dot(estimate, amplitudes) ** 2:.3f}")
for ax in axes:
    ax.axis("off")

cell 4 · a qubit budget with PCA
from sklearn.decomposition import PCA

for k in [4, 6, 8]:
    pca = PCA(n_components=k).fit(digits.data)
    print(f"PCA to {k} components keeps {pca.explained_variance_ratio_.sum():.0%} of the variance -> {k} qubits with angle encoding")
print("for comparison: 64 qubits for angle encoding of all pixels, or 6 qubits and ~57 CNOTs for amplitude encoding")

from sklearn.datasets import load_iris
from qiskit.quantum_info import state_fidelity

iris = load_iris()
flower = iris.data[0]
def amp_state(v):
    return Statevector(v / np.linalg.norm(v))
print(f"a flower and its double: fidelity {state_fidelity(amp_state(flower), amp_state(2 * flower)):.4f}")
print(f"setosa vs virginica:     fidelity {state_fidelity(amp_state(iris.data[0]), amp_state(iris.data[100])):.4f}")
print("The size of the flower is gone; only its proportions remain. Very different flowers can still look")
print("alike, because all four iris features are positive: every state sits in one corner of the sphere.")

Wrap-up

Today in one sentence

1 min
Amplitude encoding stores 2n2^n2n normalized numbers in nnn qubits, but generally costs about 2n2^n2n gates to prepare and many shots to read, so practical QML usually shrinks the data with PCA and angle-encodes what's left.
Research link

The input problem is a recurring theme: several famous quantum speedups for linear algebra assume the data is already loaded as amplitudes. When that loading is counted, or when a classical algorithm gets similar "sampling" access to the data, the advantage can shrink or vanish (Tang's "dequantization" results).

Go deeper (optional)

Aaronson, "Read the fine print" (Nature Physics, 2015), is a short, sharp essay on the input and output problems of quantum machine learning. Schuld and Petruccione's book, chapter 4.3, covers amplitude encoding and state preparation.
