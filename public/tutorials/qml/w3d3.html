Warm-up

Let PyTorch keep the books

1 min

On Monday you wrote the training loop by hand: shifts, chain rule, update. That's fine for 8 weights, but real models mix circuits with classical layers holding hundreds of weights. PyTorch (ML week 2) already knows how to differentiate classical layers. All it needs is to be told how to differentiate a circuit.

Big idea

A circuit as a PyTorch layer

4 min

PyTorch can train anything built from pieces that know two things: how to compute their output (forward) and how to pass gradients back to their inputs (backward). Its chain rule does the rest. A circuit can be such a piece:

  1. Forward: run one circuit per data point and return ⟨Z⟩\langle Z\rangle⟨Z⟩.
  2. Backward: PyTorch hands in ∂L/∂⟨Z⟩\partial L/\partial\langle Z\rangle∂L/∂⟨Z⟩ for every point. Multiply it by the circuit's own derivatives, which the parameter-shift rule gives with two shifted runs for each weight and for each input angle.

The input angles matter. Their gradients are what flow on, backwards, into a classical layer in front of the circuit, and that's how a hybrid model learns its own encoding. Today's model reads 8×8 images of handwritten 3s and 8s:

pixels→ classical (θ1,θ2)→ quantum ⟨Z⟩→ classical p(8)\text{pixels} \xrightarrow{\ \text{classical}\ } (\theta_1, \theta_2) \xrightarrow{\ \text{quantum}\ } \langle Z\rangle \xrightarrow{\ \text{classical}\ } p(8)pixels classical ​(θ1​,θ2​) quantum ​⟨Z⟩ classical ​p(8)

The classical encoder has 130 weights (a linear layer from 64 pixels to 2 numbers, squashed into angles by π2tanh⁡\frac{\pi}{2}\tanh2π​tanh), the circuit has 8, and the scale a⟨Z⟩+ba\langle Z\rangle + ba⟨Z⟩+b has 2. Training is ordinary deep learning: mini-batches of 32 images, the Adam optimizer, binary cross-entropy. Each image costs 1+2 (8+2)=211 + 2\,(8 + 2) = 211+2(8+2)=21 circuit runs per step.

The honest question. With 130 classical weights in front of 8 quantum ones, who is doing the work? Two experiments can tell: replace the circuit by a classical twin of the same size, and freeze the encoder at its random starting values.

A circuit becomes a PyTorch layer when its backward pass is the parameter-shift rule, for its weights and its inputs. The chain rule then trains the whole hybrid, and ablations show which part earns its place.

cell 1 · a circuit as a PyTorch layer, checked
import numpy as np
import torch
from torch import nn
from qiskit import QuantumCircuit
from qiskit.circuit import ParameterVector
from qiskit.quantum_info import SparsePauliOp
from qiskit.primitives import StatevectorEstimator

torch.set_num_threads(1)
LAYERS = 2
x, w = ParameterVector("x", 2), ParameterVector("w", 4 * LAYERS)
circuit = QuantumCircuit(2)
circuit.ry(x[0], 0)
circuit.ry(x[1], 1)
for l in range(LAYERS):
    circuit.ry(w[4 * l], 0)
    circuit.rz(w[4 * l + 1], 0)
    circuit.ry(w[4 * l + 2], 1)
    circuit.rz(w[4 * l + 3], 1)
    circuit.cx(0, 1)
observable, estimator = SparsePauliOp("ZI"), StatevectorEstimator()

def run(jobs):
    """jobs: list of (angles of shape (batch, 2), weights). Returns ⟨Z⟩ of qubit 1, shape (len(jobs), batch)."""
    rows = np.array([np.concatenate([W, a]) for A, W in jobs for a in A])
    evs = estimator.run([(circuit, observable, rows)]).result()[0].data.evs
    return evs.reshape(len(jobs), -1)

class QuantumLayer(torch.autograd.Function):
    """Forward: one circuit per point. Backward: the parameter-shift rule, for the weights AND the input angles."""

    @staticmethod
    def forward(ctx, angles, weights):
        ctx.save_for_backward(angles, weights)
        return torch.tensor(run([(angles.detach().numpy(), weights.detach().numpy())])[0], dtype=torch.float32)

    @staticmethod
    def backward(ctx, grad_out):
        A, W = (t.detach().numpy().astype(np.float64) for t in ctx.saved_tensors)
        jobs = []
        for k in range(len(W)):                                   # shift one weight, for every point at once
            for s in (np.pi / 2, -np.pi / 2):
                Wk = W.copy()
                Wk[k] += s
                jobs.append((A, Wk))
        for j in range(A.shape[1]):                               # shift one input angle, for every point at once
            for s in (np.pi / 2, -np.pi / 2):
                Aj = A.copy()
                Aj[:, j] += s
                jobs.append((Aj, W))
        V = run(jobs)
        d = (V[0::2] - V[1::2]) / 2                               # (weights + inputs, batch) partial derivatives
        g = grad_out.numpy()
        grad_w = d[: len(W)] @ g                                  # each weight is shared by the whole batch: sum
        grad_a = (d[len(W):] * g).T                               # each angle belongs to one point
        QuantumLayer.runs += len(A) * (1 + len(jobs))
        return torch.tensor(grad_a, dtype=torch.float32), torch.tensor(grad_w, dtype=torch.float32)

QuantumLayer.runs = 0

# check the backward pass against finite differences
A = torch.tensor([[0.3, -0.7], [1.1, 0.4]], requires_grad=True)
Wt = torch.tensor(np.random.default_rng(0).normal(size=4 * LAYERS), dtype=torch.float32, requires_grad=True)
QuantumLayer.apply(A, Wt).sum().backward()
eps = 1e-3
up, down = Wt.detach().numpy().astype(np.float64), Wt.detach().numpy().astype(np.float64)
up[0] += eps
down[0] -= eps
numeric = (run([(A.detach().numpy(), up)])[0].sum() - run([(A.detach().numpy(), down)])[0].sum()) / (2 * eps)
print(f"d(sum)/d w0: parameter shift {Wt.grad[0].item():.5f}, central finite difference {numeric:.5f}")
print("gradients for the input angles:\n", A.grad.numpy().round(4))

cell 2 · encoder, circuit, scale
from sklearn.datasets import load_digits
from sklearn.model_selection import train_test_split

digits = load_digits()
mask = np.isin(digits.target, [3, 8])
X_all = digits.data[mask] / 16.0
y_all = (digits.target[mask] == 8).astype(np.float32)
X_tr, X_te, y_tr, y_te = train_test_split(X_all, y_all, test_size=0.3, random_state=0, stratify=y_all)
X_tr, X_te = torch.tensor(X_tr, dtype=torch.float32), torch.tensor(X_te, dtype=torch.float32)
y_tr, y_te = torch.tensor(y_tr), torch.tensor(y_te)

class Hybrid(nn.Module):
    def __init__(self):
        super().__init__()
        self.encoder = nn.Linear(64, 2)                                  # classical: 64 pixels → 2 numbers
        self.weights = nn.Parameter(0.6 * torch.randn(4 * LAYERS))       # quantum: 8 rotation angles
        self.scale = nn.Linear(1, 1)                                     # classical: a⟨Z⟩ + b

    def forward(self, X):
        angles = (np.pi / 2) * torch.tanh(self.encoder(X))               # squash into [-π/2, π/2]
        z = QuantumLayer.apply(angles, self.weights)
        return self.scale(z.unsqueeze(1)).squeeze(1)                     # a logit: p = sigmoid(logit)

def fit(model, epochs=15, lr=0.05, seed=0, report=True):
    torch.manual_seed(seed)
    optimizer = torch.optim.Adam([p for p in model.parameters() if p.requires_grad], lr=lr)
    loss_fn = nn.BCEWithLogitsLoss()
    for epoch in range(epochs):
        for batch in torch.randperm(len(X_tr)).split(32):              # mini-batches of 32 images
            optimizer.zero_grad()
            loss = loss_fn(model(X_tr[batch]), y_tr[batch])
            loss.backward()                                              # classical autograd + parameter shift
            optimizer.step()
        if report and epoch % 5 == 4:
            with torch.no_grad():
                acc = ((model(X_te) > 0).float() == y_te).float().mean().item()
            print(f"epoch {epoch + 1:2d}: last batch loss {loss.item():.3f}, test accuracy {acc:.3f}")
    with torch.no_grad():
        return ((model(X_te) > 0).float() == y_te).float().mean().item()

torch.manual_seed(0)
hybrid = Hybrid()
print("parameters: classical", sum(p.numel() for n, p in hybrid.named_parameters() if n != "weights"), "+ quantum", hybrid.weights.numel())

cell 4 · the classical twin
class Twin(nn.Module):
    def __init__(self):
        super().__init__()
        self.encoder = nn.Linear(64, 2)
        self.middle = nn.Sequential(nn.Tanh(), nn.Linear(2, 2), nn.Tanh(), nn.Linear(2, 1))   # 9 parameters, like the circuit's 8 + scale

    def forward(self, X):
        return self.middle(self.encoder(X)).squeeze(1)

torch.manual_seed(0)
acc_twin = fit(Twin(), report=False)
print(f"classical twin test accuracy: {acc_twin:.3f}   (hybrid: {acc_hybrid:.3f})")
What it printed in the notebook
classical twin test accuracy: 0.991   (hybrid: 0.991)

Cell 1 checks the hand-written backward pass against a finite difference before trusting it, a good habit for any gradient you write yourself. In cell 3 the hybrid reaches 99% on the test images after about 78,000 circuit runs. In cell 4 the classical twin, with the same encoder and 9 classical weights where the circuit was, reaches the same 99%.

frozen = Hybrid()

With a random projection, the circuit and the classical twin get stuck at exactly the same 78%. The trained encoder is where the skill lives. That doesn't make hybrid models useless, but a claim that a hybrid works because of its quantum part has to show it, for example with these two experiments.

Wrap-up

Today in one sentence

1 min
Give a circuit a backward pass made of parameter-shift runs, for its weights and its input angles, and PyTorch trains it inside any hybrid model; then use a classical twin and a frozen encoder to check whether the circuit is doing the work.
Research link

Hybrid models are common in QML papers, sometimes with large classical networks around a few qubits. When you read one, look for today's two experiments. Without them, you can't tell whether the circuit matters or the classical layers did the job.

Go deeper (optional)

Mari, Bromley, Izaac, Schuld and Killoran, "Transfer learning in hybrid classical-quantum neural networks" (Quantum, 2020), which introduced the "dressed quantum circuit": classical layers on both sides of a circuit, like today's model. The PyTorch documentation's note "Extending PyTorch" explains custom autograd functions in full.
